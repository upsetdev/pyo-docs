## `pyo deploy`

Apply pyo.toml and deploy, then follow it to the end. With -f, import a Docker Compose file instead: see what it makes, then deploy it

```text
Apply pyo.toml and deploy, then follow it to the end. With -f, import a Docker Compose file instead: see what it makes, then deploy it

Usage: pyo deploy [OPTIONS]

Options:
  -s, --service <SERVICE>  The service: a name ("api", "shop/api") or id. Default: pyo.toml's
      --url <URL>          Your Pyo, e.g. https://pyo.example.com (default: the one you signed in to) [env: PYO_URL]
      --detach             Start it and exit, without following it
      --token <TOKEN>      An API key, for CI (default: the one `pyo login` saved) [env: PYO_API_KEY]
  -f, --file <FILE>        A Docker Compose file to import as a new project (a .env next to it is read too)
      --team <TEAM>        The team to import into (slug or id). Defaults to your first team
      --cluster <CLUSTER>  The cluster to run it on (name or id). Defaults to the team's default cluster
  -y, --yes                Don't ask: import the Compose file, or go ahead with a very large replica change from pyo.toml
  -h, --help               Print help
  -V, --version            Print version
```

Set the variables of a .env file.

New keys are variables unless marked secret. A secret that's overwritten stays a secret. In a terminal, you're asked about keys that are already set. Elsewhere, pass --overwrite or --skip-existing.

Arguments:
  [FILE]
          [default: .env]

      --overwrite
          Overwrite keys that are set already

      --url <URL>
          Your Pyo, e.g. https://pyo.example.com (default: the one you signed in to)
          
          [env: PYO_URL]

      --skip-existing
          Keep keys that are set already

      --token <TOKEN>
          An API key, for CI (default: the one `pyo login` saved)
          
          [env: PYO_API_KEY]

      --secret <KEY>
          Make this key a secret (repeatable)

      --secrets
          Make every key a secret

      --dry-run
          Show what would change, without saving

      --deploy
          Deploy right away

  -s, --service <SERVICE>
          The service: a name ("api", "shop/api") or id. Default: pyo.toml's
