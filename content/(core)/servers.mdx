## Add a server

Open a cluster and add a server. Pyo gives you a command to run on the new machine, which joins it to the cluster over [Tailscale](/docs/tailscale). Adding a server needs Tailscale set up in Pyo. The command carries a single-use key, valid for an hour. The server gets the same [memory reserve for k3s](/docs/system-reference#k3s) as the cluster's first server.

Or let Pyo make the server for you at [Hetzner](/docs/hetzner).

## Tags

Add tags to servers, like `gpu`. You can then [place](/docs/scaling#choosing-where-services-run) services by tag, region or server name.

## Regions

Pyo detects each server's region from its address. To group servers your own way, rename it with **Change region** in the server's menu. Replicas spread across regions, and each region's traffic is answered there by default. See [Serving traffic by region](/docs/regions).

Every server answers requests for your sites through [Pyo Gateway](/docs/gateway), except build-only servers. Whether the cluster takes public traffic at all is a [cluster setting](/docs/clusters#public-traffic).

## Maintenance

From a server's page you can:

- **Pause scheduling**, so no new replicas land on it.
- **Mark it for maintenance.**
- **Drain it**, moving its services to other servers.
- **Remove it** from the cluster. Then uninstall k3s on the machine, as in [Remove a server](/docs/uninstall#remove-a-server).

## Low disk space

A server that runs low on disk space stops some of what runs on it to free space. Pyo keeps the parts that serve and report running through it:

- [Pyo Gateway](/docs/gateway), so your sites keep answering
- the [WAF](/docs/waf) and [websites on your tailnet](/docs/tailscale#websites-on-your-tailnet)
- the agent and the log collector, so the server keeps reporting to Pyo

Your services aren't protected this way. Below 5% free disk, the server may stop some of their replicas. With other servers in the cluster, Pyo starts them there.

Pyo tells you in **Activity**, like "web-1 is low on disk space", and again when the server has enough. It can also send an [alert](/docs/alerts). The server's page shows its **Disk** condition.

What Pyo cleans up by itself:

- Images no service uses. Cleanup starts when the disk is 85% full and goes on until it's down to 75%.
- The stopped replicas left behind when a server was short of disk.

What you should do:

1. Find what fills the disk. It's often something outside Pyo, like old logs, downloads or another program's data.
2. Free that space, or give the server a bigger disk.
3. If a service's own data fills it, move that data to a [volume](/docs/volumes).

The server counts as low on disk until it has 1 GiB more than the 5% free. Then it runs services again.

A server gets these settings from its setup command. To apply them on a cluster's first server that was set up earlier, run the command under [Refresh this cluster](/docs/clusters#refresh-a-cluster).

This works the same on Pyo Cloud, since it all happens on your own servers. Everyone in the team sees the activity. Team owners and admins set up alerts.
