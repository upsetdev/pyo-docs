## Analytics

**Analytics**, in the sidebar's **Observability** menu, measures your sites from the web server's own logs, so there's no script to add. You get visitors, pages, <Term tip="The sites visitors came from, like a search engine or a link on social media.">referrers</Term>, countries, devices and browsers. **Server errors** is the share of requests answered with a 5xx status. Logs show 4xx and 5xx apart.

Visitors are counted with a <Term tip="A one-way code made from the visitor's IP address, browser and your site, mixed with a value that changes daily. It tells visits apart but can't be traced back to anyone.">hash</Term> that changes daily. Visitor IP addresses aren't kept by default. An admin can change what's kept under **Settings → Observability**.

## Connections

A service with public TCP or UDP ports has a **Connections** card on its **Overview**, for the ports that go through [Pyo Gateway](/docs/gateway#tcp-and-udp-ports). It shows connections, clients and data over time. Each connection shows its country, bytes, duration and outcome: ok, blocked, limited or unreachable. Blocked means the [firewall](/docs/firewall) or a port's IP rule stopped it.

A TCP connection is counted when it closes. A UDP exchange is counted once it's been quiet for a minute, and its duration includes that minute. Ports that skip the gateway aren't counted.

## Request logs

**Request logs**, in the sidebar's **Observability** menu, shows the web server's log of every request your sites served: the time, method, URL, status, response time and size, with the visitor's browser and country. Search and filter them to find a request. Sensitive values in query strings are hidden. They're kept on each cluster, for 7 days or up to 1 GB by default. Change both under the team's **Settings**. Request logs ask the cluster when you open them, so they need it online.

The totals above the log, like requests and errors, are counted once a minute is over. They show the time they count up to. The last minute or two of requests are in the log before they're in the totals.

These are request logs, not your service's own output. Service logs are on each service. New lines show as they're printed, over one stream from the cluster. Open them from the service, or use the CLI:

```bash
pyo logs --follow
```

## Metrics

See CPU and memory for each server and service, and for [Pyo Gateway](/docs/gateway), which handles all web traffic into each cluster. The gateway has no limit of its own, so its use is shown against the cluster's total capacity.

## How long it's kept

An admin chooses how long Pyo keeps history, under **Settings → Observability**:

| | Default | Choices |
| --- | --- | --- |
| Analytics | 12 months | 3, 6, 12 or 24 months |
| Metrics | 30 days | 7 to 90 days |
| Build logs | 90 days | 30 to 365 days |

Analytics includes connections and firewall and WAF history. Metrics cover servers, services and databases.

A team can keep its analytics for less time under its own **Settings**: 3, 6 or 12 months, never longer than the installation. Older analytics go each night. On [Pyo Cloud](/docs/cloud/data), this is the only retention you set.

## Turning it on or off

Analytics, Request logs, connections, firewall and WAF history and metrics over time all need Pyo's observability, which stores what each cluster's servers send. It's on unless a new install's server has less than 3.5 GB of memory. There it starts off to save memory.

An admin turns it on or off under **Settings → Observability**, or with the CLI:

```bash
pyo observability off
```

While it's off:

- Pyo stops collecting and frees the memory it used, about 150 MB on the server Pyo runs on and a little on each server.
- Analytics, Request logs and the charts over time say it's off.
- What was stored is kept. Turn it back on to see it again, with a gap for the time it was off.
- Everything else keeps working: your services' own logs, current CPU and memory, deploys, the firewall and the WAF.

Pyo never turns it on or off by itself after the install. If the server's memory changes, **Settings → Observability** suggests turning it on or off.

## Terminal

Open a <Term tip="A command line inside the running service, where you can type commands as you would on a server.">shell</Term> in any running service from the dashboard, or from your terminal:

```bash
pyo exec
```

## Activity

**Activity**, in the same menu, records who deployed or changed what, and when.
