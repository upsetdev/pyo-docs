A cluster is one or more servers running <Term tip="A lightweight version of Kubernetes, the standard system for running containers across servers. Pyo sets it up for you.">k3s</Term>. A team can have several, such as `production` and `staging`, all in one dashboard.

## The server Pyo runs on

On a fresh install, the server Pyo runs on is connected for you as your first cluster, named after its hostname. Rename it in its **Settings** tab.

## Add a cluster

Choose **Add cluster** to get a command that sets up k3s and the Pyo agent on a new machine:

```bash
curl -fsSL https://your-pyo/install/connect.sh | bash -s -- --api <pyo-address-for-servers> --token <token>
```

Copy the command from the dashboard, which fills in your Pyo's address and these values. The `--api` address is where the new machine reaches Pyo. It can differ from the address you use in your browser. It's Pyo's name on your tailnet, like `https://pyo.tail1234.ts.net`. Connecting a cluster needs [Tailscale](/docs/tailscale) set up in Pyo. The command carries a single-use key that joins the machine to your tailnet. A public address must use `https://`. Plain `http://` works only for a private network or tailnet address. The command works once, for an hour. If it expires, the cluster offers a new one. The script asks for `sudo` when it needs root. The agent connects out to Pyo, so you don't have to open anything on the machine.

If something on the machine already serves sites on ports 80 and 443, like nginx, ingress-nginx or k3s's Traefik, the command connects the cluster with [public traffic](#public-traffic) off, so those sites keep working. It leaves the machine's firewall as it is and says so in one line:

```text
● Ports 80 and 443 are in use by Traefik. Public traffic stays off, so your sites keep working.
```

Pyo installs its own cert-manager and Pyo Gateway. If the machine already runs cert-manager or Envoy Gateway that Pyo didn't install, the command stops before it changes anything. Pyo won't change them:

```text
This server already runs cert-manager that Pyo didn't install. Pyo won't change it. Remove it, or connect a server without it.
```

Remove it and run the command again, or connect another server.

Pyo can also make the cluster's first server at [Hetzner](/docs/hetzner).

## Inside a cluster

Open a cluster from **Clusters**. Its tabs are:

| Tab | What it shows |
| --- | --- |
| Overview | Its state at a glance |
| Servers | The machines in it |
| Workloads | Everything running, down to the server it's on. See [Workloads](#workloads) |
| Networking | HTTP routes and ports |
| Storage | Volumes and storage classes |
| Settings | Its details, public traffic, free domains, how traffic is routed, mTLS, its connection and removal |

### Workloads

The **Workloads** tab opens on your team's **Services**, with their project, kind, status, CPU and memory. Switch to **System** to see what Pyo and the cluster run themselves. Each part is one row, with its replicas, CPU and memory added up and the worst status among them:

| Part | What it is |
| --- | --- |
| Agent | The Pyo agent that runs the cluster for Pyo |
| Builds | Builders and Pyo's registry |
| Databases | What runs your databases |
| Gateway | [Pyo Gateway](/docs/gateway), certificates, the WAF and static sites |
| Logs | What collects request logs, analytics and metrics |
| Pyo | Pyo itself, on the server it runs on |
| Cluster | Everything else the cluster runs, like k3s's DNS |

## Traffic [#public-traffic]

Traffic reaches your cluster's websites on up to three paths. Turn each on or off under **Settings › Traffic**. A cluster always keeps one on. Until Tailscale is set up, the card links to **Integrations**.

- **Public ports**: ports 80 and 443 on every server except [build-only servers](/docs/builders#where-a-builder-can-run). Point your domains at any of them. Every server runs [Pyo Gateway](/docs/gateway) there, with your public TCP and UDP ports. **Accept PROXY protocol** only if every connection comes through a load balancer that sends it. Saving it drops open connections once. With public ports off, **Publish TCP and UDP ports** keeps your services' TCP and UDP ports on the servers.
- **Cloudflare Tunnel**: websites through Cloudflare, with no open ports. See [Cloudflare Tunnel](/docs/cloudflare-tunnel).
- **Tailscale**: websites on ts.net names and on your servers' Tailscale addresses. Servers stay on your tailnet when it's off. See [Tailscale switch](/docs/tailscale#tailscale-switch).

Each domain takes one path. When you turn off a path that domains use, Pyo lists them first. A domain whose path is off shows **Not served** and keeps its settings. Turn the path on again to serve it.

With public ports off, services keep running without a restart. They still reach each other inside the cluster on all their ports. On the server Pyo runs on, the dashboard and registry stay reachable over your [tailnet](/docs/tailscale). Let's Encrypt can't renew certificates over HTTP until public ports are back on.

If another program in the cluster still holds ports 80 and 443 on a server, like k3s's Traefik, the gateway can't get them there. The cluster's **Networking** tab and its setup checklist then say `Ports 80 and 443 are in use on <server>`, and so does `pyo status`. Your services' sites don't answer on that server until you stop that program. The gateway takes the ports once they're free. Or use **Cloudflare Tunnel**, which needs neither port.

Pyo doesn't check whether a server can be reached from the internet. A server with only a private or tailnet address runs the gateway too. It answers anyone who can reach that address.

Team owners and admins can change it, and each change is recorded in **Activity**.

## Refresh a cluster

A cluster's **Settings** tab shows the command under **Refresh this cluster**. Run it on the cluster's first server to apply Pyo's latest host settings, like the [memory reserve for k3s](/docs/system-reference#k3s):

```bash
curl -fsSL https://your-pyo/install/connect.sh | bash
```

The dashboard fills in your Pyo's address. It reads the agent's token from the agent already there. On the server Pyo runs on, the address is `http://127.0.0.1:8000`.

After some updates, a cluster shows **Update needed** until you run this command. The server Pyo runs on runs it by itself after an update. If the update moves your databases to new images, the panel says **Restarts your databases once**. See [Refresh a cluster after an update](/docs/updating-pyo#refresh-a-cluster-after-an-update).

## Reconnecting

Rotating a cluster's token from its **Settings** tab stops the current token from working. Run the new command to reconnect the agent.

## Disconnecting

**Remove cluster**, on its **Settings** tab, deletes nothing on the cluster. Its servers leave your tailnet, as in [Removing a cluster](/docs/tailscale#removing-a-cluster). To also remove what Pyo put into it, see [Disconnect a cluster](/docs/uninstall#disconnect-a-cluster).

Pyo removes a cluster once its services are deleted or moved. If a cluster has been unreachable for 10 minutes, you can remove it with its services. Choose **Remove anyway** and type its name. Pyo forgets the cluster and its services, databases and volumes. Anything still running there is left alone.

## High availability

Extra servers only run services, so a cluster has one <Term tip="The server that runs the cluster itself and decides what runs where. The others only run services.">main server</Term>. If that server goes down, services on other servers keep running. Deploys and <Term tip="Moving services from a failed server to healthy ones.">rescheduling</Term> stop until it's back.
