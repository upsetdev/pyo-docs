---
title: Configuring your installation
description: Settings for your whole installation, set by its admin.
---

The account you set up after installing owns the installation. Its settings are under **Settings**, a page each at the root of the dashboard, like `/backups` or `/email`. Only installation admins see them. They apply to every team:

- **[GitHub](/docs/github):** the <Term tip="A kind of GitHub integration with its own permissions, installed on the accounts and repositories you choose.">GitHub App</Term>.
- **[Email](/docs/email):** the <Term tip="The server that sends email for you. Your email provider gives you its host, port and login.">SMTP server</Term> for invites, sign-in links and security emails.
- **[Backups](/docs/backups#backing-up-pyo-itself):** encrypted copies of Pyo's own data.
- **[Observability](/docs/observability#turning-it-on-or-off):** whether Pyo keeps analytics, logs and metrics over time, [how long](/docs/observability#how-long-its-kept), and what they keep about visitors. It starts off on a new install with less than 3.5 GB of memory.
- **Security:** whether every account must use [two-factor authentication](/docs/two-factor#require-it-for-everyone), where [admins can sign in from](/docs/admin-sign-in), and how long the [audit log](/docs/audit-log#how-long-its-kept) keeps entries.
- **[Updates](/docs/updating-pyo):** new releases of Pyo, by hand or on a schedule.

Everything else is set with environment variables, listed in the [system reference](/docs/system-reference).

## Sign-ups

Only people you invite can sign up. To let anyone with access to the dashboard create an account, run this on the server:

```bash
sudo k3s kubectl -n pyo-system set env deployment/pyo PYO_ALLOW_SIGNUP=true
```

## Visitors

Each team chooses what its servers keep of visitors, under its **Settings → Observability**. The admin sets a default for teams that didn't choose, and a limit no team can go above, under **Settings → Observability**.

| IP addresses | What's kept |
| --- | --- |
| Don't store | Nothing that identifies a visitor (recommended, and the default) |
| Anonymized | The address without its last part, which points to a network, not a person |
| Full | The whole address, kept with each team's [request logs](/docs/observability#request-logs) for up to 31 days. May need consent under laws like <Term tip="The European Union's data protection law.">GDPR</Term> |

| Query strings | What's kept |
| --- | --- |
| Keep | Parameter names and values (the default) |
| Names only | Parameter names, like `?q&page` |
| Don't keep | Nothing after the path |

Passwords, tokens and other sensitive values are always hidden.

Until the admin sets a limit for IP addresses, the default is also the limit. Lowering a limit applies at once: addresses are hidden when read, and new requests follow within about a minute. Each team that keeps less gets an entry in its activity. Changing a default moves only the teams that didn't choose.
