Pyo's MCP server has 193 tools. They act as the person who approved the assistant, with the same permission checks as the dashboard.

An assistant only sees the tools its access allows: 43 with **Read only**, 53 with **Deploy**, 57 with **Sandboxes** and all 193 with **Full**. See [access](/docs/mcp#choose-what-it-can-do).

The sandbox tools show once your team can use a [sandbox server](/docs/sandbox).

Most tools do the same as an API operation, and take the same fields. Its reference page lists them.

Hetzner Cloud servers have no KVM, so it runs sandboxes on gVisor. Follow it in the server's `cloud` (creating, booting, joining, ready) and `state`. Without `confirm` it answers 409 with the monthly price. Confirm that with the user, then send it again with `confirm: true`. Team owners and admins. Needs Tailscale and the team's Hetzner connection. | Full | [Reference](/docs/api/reference/sandboxes/create-cloud-sandbox-server) |
| `create_sandbox_template` | A template made from an OCI image, like "node:22", or an image in Pyo's registry. Every sandbox server that may use it pulls the image and makes a root disk from it. A Firecracker server boots it once and snapshots it, and a gVisor server starts sandboxes from the disk. The template is ready once one server has it. | Sandboxes | [Reference](/docs/api/reference/sandboxes/create-sandbox-template) |
| `delete_sandbox_template` | Deletes it here and on the sandbox servers. Refused while sandboxes run from it. | Sandboxes | [Reference](/docs/api/reference/sandboxes/delete-sandbox-template) |
| `extend_sandbox` | Sets when the sandbox ends: `ttl` from now, or never with `"none"`. | Sandboxes | [Reference](/docs/api/reference/sandboxes/extend-sandbox) |

| `list_sandboxes` | A team's sandboxes: their template, size, state, server and lifetime. Env values are never shown, only their names. | Read | [Reference](/docs/api/reference/sandboxes/list-sandboxes) |
| `remove_sandbox_server` | Deletes its sandboxes where it still answers, and forgets it. To take the daemon off the server, run `sandbox.sh --uninstall` there. A server Pyo made at a cloud provider leaves your tailnet and is deleted there, which takes `confirm`. | Full | [Reference](/docs/api/reference/sandboxes/remove-sandbox-server) |
