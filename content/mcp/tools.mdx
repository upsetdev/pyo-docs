Pyo's MCP server has 129 tools. They act as the person who approved the assistant, with the same permission checks as the dashboard.

An assistant only sees the tools its access allows: 29 with **Read only**, 38 with **Deploy** and all 129 with **Full**. See [access](/docs/mcp#choose-what-it-can-do).

Most tools do the same as an API operation, and take the same fields. Its reference page lists them.

UDP ports and ports that bypass the gateway aren't counted. | Read | [Reference](/docs/api/reference/firewall/get-firewall-blocked) |
| `get_waf_hits` | What a service's web application firewall found: requests it blocked, and ones it only logged in log-only mode. It shows them over time (`series`), per rule, domain, source, country and path, and the latest 50 with the rules that matched. `custom` shows how often each custom rule matched, by its number. Query strings are kept with sensitive values redacted. | Read | [Reference](/docs/api/reference/firewall/get-waf-hits) |
| `remove_firewall_rule` | Remove a firewall access rule. | Full | [Reference](/docs/api/reference/firewall/remove-firewall-rule) |
| `remove_waf_rule` | Remove a custom web application firewall rule. | Full | [Reference](/docs/api/reference/firewall/remove-waf-rule) |
| `reorder_firewall_rules` | Put a service's firewall access rules in this order: allow and block rules are checked from the first. List every one of its rules. | Full | [Reference](/docs/api/reference/firewall/reorder-firewall-rules) |
| `reorder_waf_rules` | Put a service's custom web application firewall rules in this order. List every one of its rules. | Full | [Reference](/docs/api/reference/firewall/reorder-waf-rules) |
| `set_service_waf` | A service's web application firewall (WAF) settings, for all its domains. | `update_firewall_rule` | Change a firewall access rule. Omitted fields stay as they are (as in `addFirewallRule`). | Full | [Reference](/docs/api/reference/firewall/update-firewall-rule) |
