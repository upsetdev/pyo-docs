Every endpoint here is a `GET` under `/api/v1`.

## Snapshot

`GET /state` returns everything you can see: teams, projects, clusters, servers, services and recent deployments. Most scripts only need this one.

```bash
curl https://your-pyo/api/v1/state \
  -H "Authorization: Bearer $PYO_API_KEY"
```

## Service logs

`GET /services/{id}/logs` returns the recent output of a service's running <Term tip="One running copy of a service. More replicas share the traffic and keep it up if one stops.">replicas</Term>. It takes `since`, `replica` and `tail`.

To follow them, open a WebSocket at `/services/{id}/logs/follow` with the same query. It sends the last lines, then new ones as they're printed. Each text frame is `{"type":"lines","lines":[…]}`, or `{"type":"error","message":…}`. It closes after an hour, so open it again with `since` set to the newest line's time. `pyo logs -f` and the dashboard follow logs this way.

## Database logs

`GET /databases/{id}/logs` returns a database's recent output and its events. To follow them, open a WebSocket at `/databases/{id}/logs/follow`. It works like a service's, and also sends all events as `{"type":"events","events":[…]}` whenever they change.

## Metrics

`GET /metrics` returns CPU and memory over time for a team's servers and services.

| Parameter | Description |
| --- | --- |
| `team` | The team (required) |
| `cluster` | A cluster id, or `all` |
| `range` | The time range, such as `24h` |

## Observability

`GET /observability` returns traffic for a team's websites: a `summary`, a `series` over time, and the `previous` period to compare with. A read key is enough.

| Parameter | Description |
| --- | --- |
| `team` | The team (required) |
| `project` | A project id, or `all` |
| `service` | Limit it to one service's domains |
| `site` | A domain id, or `all` |
| `range` | `1h`, `24h`, `7d` or `30d` (default `7d`) |

If the installation has no ClickHouse set up, it returns `503`.

`GET /observability/domains?team=...` returns each domain's requests over a `range` (default `24h`) with a `series` over time, busiest first. It lists only domains that had requests. While observability is off, the list is empty.

## Request logs

`GET /access-logs` returns the requests your sites served, newest first. It takes `team`, `project`, `service`, `site` and `range` like observability, plus `status`, `method`, `limit` and `before` for paging back.

## Audit log

`GET /audit-log?team=...` returns who did what in a team, newest first, 100 at a time. Only the team's owners and admins get an answer. See [Audit log](/docs/audit-log#api-and-assistants) for its parameters.

## Images

`GET /images?team=...` lists the container images a team's services have run, with each version deployed.
